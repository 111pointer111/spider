# 提问统计的边界

Spider 目前直连用户配置的 AI 端点，没有经过维护者的服务器。因此维护者无法获取所有用户的历史提问次数；插件下载量也不代表独立用户数或活跃人数。

截至 2026-10-07 查阅的 [Obsidian 官方开发政策](https://docs.obsidian.md/community-directory/developer-policies)明确指出，社区插件禁止捕获客户端遥测数据。本版本不添加每次提问自动上报、匿名设备 ID 或统计 SDK，也不将自愿开启的遥测开关视为当然允许。

可考虑的后续方案：

1. **本地统计与主动反馈**：为用户显示本笔记库的提问次数，用户主动提交反馈时自行提供。只能反映参与反馈的用户，不能称为全用户总量。当前本地已存图谱可数出保留的 user 消息，但删除过的图谱无法恢复，重试和摘要应单独定义口径。
2. **真实提供 AI 服务**：如果未来提供可选的托管 AI 服务，可以在处理实际 AI 请求的服务端统计用量。发布前需要重新确认官方开发政策、披露服务端统计并提供隐私政策。只能覆盖使用该服务的用户，不能计入直连其他服务的请求。不要仅为采集行为而让原本的直连请求绕过维护者服务器。

若采用服务端统计，先定义「一次提问」：用户首次发送问题、重试、成功回复、自动标题和摘要分别计数，使用服务端请求 ID 去重，汇总时说明统计起点和覆盖范围。历史数据无法追溯补齐。
